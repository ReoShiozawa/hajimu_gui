## 検証方針

### 他言語のGUIライブラリとの比較

比較対象はC++のQt WidgetsとCのGTK 4。以下は機能の有無だけでなく、実アプリの安全性と操作の一貫性を基準にした優先順位であり、同等対応を宣言するものではない。

| 優先 | 必須の基盤 | 比較対象の契約 | hajimu_guiで不足している点 |
| --- | --- | --- | --- |
| 最優先 | 入力配送/捕捉 | [GTKのイベント配送](https://docs.gtk.org/gtk4/input-handling.html)は対象と伝播/消費を区別 | 世代付き配送と共通/アプリ別キューの超過リセットを追加したが、全ウィジェットの消費規則、複数モーダル、他OS実機は残る |
| 最優先 | 日本語と通常の文字編集 | [QtのIMEイベント](https://doc.qt.io/qt-6/qinputmethodevent.html)は未確定/確定/置換範囲を区別 | 共通入力の書記素単位編集を追加。macOSの接続は部分対応で、字形合成、実IME操作、長い未確定文字、Windows/Linuxの接続が必要 |
| 高 | キーボード操作 | [Qtのフォーカス](https://doc.qt.io/qt-6/focus.html)はTab順序や部品別ポリシーを持つ | 基本部品のみ。全操作部品とモーダル範囲への統一、実キー操作の検査が必要 |
| 高 | 固まらない処理と寿命 | [QFutureWatcher](https://doc.qt.io/qt-6/qfuturewatcher.html)は完了/進捗/取消などを通知 | POSIXプロセスタスクは部分対応。Windows、購読、Kanameの重い処理への適用とループ外終了の同期待機が残る |
| 高 | 自動レイアウト | [Qtのレイアウト](https://doc.qt.io/qt-6/layout.html)は内容変更や表示切替でも配置/サイズを再計算 | 幅制約とクリッピングだけでは不十分。内容計測、縦制約、折返し、一般フォームへの適用が必要 |
| 高 | 共通コマンドと編集履歴 | [QAction](https://doc.qt.io/qt-6/qaction.html)と[Undo Framework](https://doc.qt.io/qt-6/qundo.html) | 保存以外の操作統一、文脈階層、複合操作の境界をKaname全体へ適用する必要がある |
| 高 | 支援技術との接続 | [Qtのアクセシビリティ](https://doc.qt.io/qt-6/accessible.html)はキーボード操作や拡縮も含む | macOSの基本部品/入力欄に限定。外部AX/VoiceOver、テーブル/ツリー、UIA/AT-SPIが必要 |

追加の装飾部品やアニメーションより先に、上記の契約を検証する。API名の登録や固定成功値だけを実装済みと数えない。

### 入力配送の更新 (14.24.0)

- macOS/Windows/Linuxの送出イベントに送信元ウィンドウと世代を付け、破棄済み/不一致の対象を拒否する。
- 別ウィンドウ向けイベントを各アプリの通常64件キューへ移す。連続マウス移動を集約し、最新サイズと終了要求は別保持する。
- 保留超過時は中途半端なキー/置換列を全破棄し、次の処理で入力/フォーカス/捕捉/IMEをリセットする。ファイルパスは消費/破棄時に解放する。
- OS終了要求は編集コールバック後に確認し、直前に確定した文字が保存モデルへ反映されてから確認を呼ぶ。
- `アプリ入力状態` で通常保留数・保留超過破棄数・不正配送拒否数・リセット待ちを公開。破棄したウィンドウには有効=falseを返す。
- ASan/UBSanでキュー所有権/1万回循環/上限、実ウィンドウ試験で別配送・古い世代・編集後の終了・超過リセット・GL描画先復帰を検査する。
- WindowsはMinGWの構文検査、LinuxはmacOS上のX11ヘッダーによる構文検査まで。実OS操作を検証済みとしない。
- ネイティブ共通キュー自体の容量超過、全画面同時描画、異なる描画ループの入れ子で共有状態を完全に分離することは未完了。Linuxの長いIME確定は安全に拒否するが、全文配送の完成ではない。

### 共通キューと入力取得の更新 (14.25.0)

- 14.24.0で残していたネイティブ共通キュー超過へ対応。通常255件とは別に、最大32の登録ウィンドウについて終了/最新サイズ/リセットを保持する。世代不一致は配送しない。
- 超過時は未処理の入力列を全破棄し、全登録ウィンドウへリセットを通知する。GUIで保留していた古い文書置換も、適用前に破棄する。
- `アプリ入力状態` の `OSキュー破棄入力数` は、そのウィンドウの入力のうちOS共通キュー超過で破棄され、GUIへリセット通知済みの累積数。破棄した入力を復元する機構ではない。
- 取得と消費を分離し、GUIフレームごとのOS取得は1回・最大256件まで。個々のOSコールバックやアプリコールバックの実行時間保証は別課題である。
- キー/マウスのポーリング状態はリセット時に保守的に中立化する。Windowsのマウス捕捉と未完サロゲートを解除し、macOSの文書/未確定状態を解除する。LinuxのXIM全文編集やOS別の実IME統合は未完了。
- 共通CキューをASan/UBSanで検査し、複数ウィンドウのリセット/損失数、終了/サイズ保持、ファイル所有権、古い世代、1万回循環を確認する。
- macOSでは1000件を再投入するCocoaイベントで取得回数上限を検査し、文書/未確定文字/押下の解除と、実描画ループで古い保留置換を適用しないことを確認する。
- Windows/Linuxは構文検査まで。全画面同時描画、入れ子ループの共有状態分離、複数モーダル、全ウィジェットでのイベント消費は引き続き未完了。

### 複数モーダルと範囲付き描画 (14.27.0)

- `モーダル予約` は親から子の文字列配列を受理する。最大16段を検証してから一括適用し、型/空名/重複/長さ/上限の違反では既存状態を保持する。従来の文字列と空文字も維持する。
- `モーダルスタック` は固定空配列を廃止し、予約順序の独立したスナップショットを返す。容量も初期化し、呼出側の配列追加で内部状態を変更しない。
- 各段の移動前フォーカスを保存し、子を閉じると親、全解除で元の入力へ復帰する。編集位置は入力欄の状態を維持し、次フレームに対象が表示されない/無効なら解除する。
- `ダイアログ開始` / `ダイアログ終了` で描画と入力の範囲を明示する。親を描画しても最前面以外は入力/ナビゲーション/AXを抑止し、名前ごとにIDを分離する。
- 外側のクリップに依存せず中央へ描画し、内容の可視/入力領域を自身の矩形へ制限する。外側の基本レイアウト/ID/無効化/描画状態を復帰する。
- 終了時の余った入力は消費する。同フレーム再入、無効化領域を抜ける際の入力再配送、閉じた段のスクロール状態で新しい予約を上書きすることを防ぐ。
- 未閉鎖の子領域は終了時に回復して偽を返し、フレーム末尾にも範囲を回復する。描画状態上限では開始を失敗させ、状態を変更しない。
- ASan/UBSanで段の変更/上限/不正入力、フォーカス復帰/非表示解除、ID分離、入力消費、祖先領域の復元、閉じ忘れと状態上限を検査する。公開APIと描画画像でも二段の独立入力/全体表示を検査する。
- 旧 `ダイアログ` の暗黙範囲、任意のキャンバスなど特殊な状態、OSキーを直接読む旧部品の統一、Kaname全画面への移行、全OSの実操作は残る。モーダル/イベント/フォーカス項目全体を完了扱いにしない。
- 14.26.0のWindows CIで発生した自動CRLF変換を原本のバイト保持で修正し、Windows/macOS/LinuxのビルドとUnicode公式境界テストの成功を実CIで確認した。これは各OSのGUI操作を検証したことを意味しない。

### 書記素単位編集 (14.26.0)

- utf8proc 2.12.0 / Unicode 18.0.0を固定コミットで同梱。自前の境界規則ではなく、状態付き判定を境界ごとに初期化してRI/ZWJ/Indic結合列へ対応する。
- 共通の単一行/複数行/パスワード入力で左右移動・Shift選択・Backspace/Delete・マウス位置指定を接続。明示APIで書記素内部に位置を置いた後の範囲未選択削除も分断しない。
- 書記素単位のマスクと折返しへ統一。CRLFを1つの改行として次行位置へ進め、容量不足時の初期値/共通入力/貼付けの切詰めは完全な書記素までに限定する。
- Unicode公式GraphemeBreakTest 853件について全バイト位置の前後/切上げ/切下げをASan/UBSanで検査。不正/途中切れUTF-8でも範囲内で前進する。
- GUIの結合濁点/アクセント/肌色/国旗/ZWJ/Indic/CRLFについてキー操作、通常/マスク位置指定、狭い幅の折返し、容量、API互換性を検査する。
- 公開位置APIのUnicode符号位置単位とIME/AXの明示範囲指定は維持する。全ウィジェットへの編集統一、OS側のUnicode規則との差、実IMEとOS実操作は未完了。
- 描画画像で通常欄・3書記素のマスク・複数行が表示されることを確認。ただし結合アクセントの配置に既存の描画問題があり、字形合成/複雑な文字組み/合字/双方向文字は別の必須残課題とする。書記素境界の合格を描画の完成根拠にしない。
- 依存ソース・Unicodeテスト・ライセンスのハッシュを検査し、配布/インストール先にもライセンスを収録する。macOS/Linuxでは依存の公開シンボルを隠し、他プラグインとの衝突を避ける。

### 検証上の注意

描画ループ内の終了に待機状態を追加し、WNOHANGでタスクを回収する間もOSイベントと待機画面を描画する。

遅延/停止失敗を注入した実描画ループ試験で、複数待機フレーム、コールバック抑止、確認一回、失敗後の復帰/再終了、回収前の破棄なしを検査した。

`tests/test_async_shutdown.jp` は公開API経由で終了要求と回収後の状態、確認の重複防止を検査する。
描画ループ外の明示破棄は同期契約を維持。複数ウィンドウ全体の配送、他OS実機、独立した子孫、任意関数隔離、Kanameの重い処理への実適用などが残り、非同期/寿命項目全体は未完了。

通常の取消を要求と回収に分離し、「取消中」を追加。受理後は待たずに戻り、PIDと出力を保持したままWNOHANGで回収する。
回収前の解放と完了通知を拒否し、回収後は実終了コードを返して一度だけ通知する。取消失敗時にPIDを捨てず、実行状態/エラーを保持する。
ネイティブ試験へ遅延回収とSIGKILL要求失敗を注入し、取消呼出の即時復帰、複数描画フレーム中の通知抑止、解放拒否、回収後の一回通知とFD/子回収を検査する。
